# Quality rules

## 正解

- 計算問題は、問題文の数値を自分で計算し直す。
- 単位換算は基準単位にそろえて確認する。`acceptedUnits` の倍率は
  「その単位の1単位 = 正解単位で何か」。
- 有効数字を要求するなら、問題文に桁数を書く。整数末尾0の扱いは
  Workbook 2 の仕様（書かれたとおりに数える）に従う。
- 別解があり得るなら `accepted` / `orders` / `alternatives` に入れる。
- 正解を確認できない問題は完成品に入れない。確認が必要ならその旨を明記する。

## 問題文

- 一読で聞かれていることを特定できる。主語・条件・単位を省略しない。
- 不要なひっかけや、日本語の曖昧さで間違える問題を作らない。
- 同じ内容の選択肢を並べない。
- 正解だけ極端に長い・詳細にしない。

## 解説

- 正解の理由を書く。答えの繰り返しだけにしない。
- 間違えやすい点、使った公式、次の一歩を含める。
- 15文字未満の解説は Linter が Warning にする。
- 図の読み取り問題では、図のどこを見るかを説明する。

## 図表

- 装飾のための画像を入れない。学習目標に必要な図だけ。
- 地図・回路図・グラフは、画像の見た目と正解データを照合する。
- SVG は静的な図形だけで作る。外部 URL、スクリプト、CSS を使わない。
- AI 画像生成だけで正確な図を済ませない。再現可能な SVG を優先する。
- 出典・ライセンスを記録する。

## FSRS と Near Miss

- FSRS の内部状態（ stability, difficulty, due ）を教材側で操作しない。
- 問題の難しさと Again / Hard / Good / Easy を混同しない。
- 正解が複数ある場合は許容解を設定し、Near Miss で不当に Again にしない。
- 単位・有効数字の要求は問題文に明記する。
- ヒントは答えそのものではなく、考え方の手がかりにする。

## Linter の扱い

- Error は必ず修正する。
- Warning は誤検知もある。意図的に残す場合は、教材の意図と確認方法を添える。
- `--strict` は CI 用。Warning を放置したまま完成扱いにしない。
- 自動修正は正解・解説・単位・有効数字・座標を推測で書き換えない。
