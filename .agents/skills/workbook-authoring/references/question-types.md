# Question types

形式は「作れるから使う」のではなく、学習目標に合わせて選ぶ。

## single_choice / multiple_choice

- 用語の識別、原因の選択、資料の読み取り。
- 選択肢は2〜6個。`multiple_choice` は正解1〜6個。
- 選択肢の長さと情報量をそろえる。正解だけ極端に長くしない。
- `content` は Markdown / Math / Image / Code の Content を使える。

## true_false

- 概念の誤解を確かめる。単なる「正しい文章を暗記したか」だけにしない。
- 誤文は、よくある勘違いを再現する形にする。

## short_text

- 漢字の読み、用語、英単語、短い和訳。
- `accepted` に表記揺れ・別解を入れる。意味の自動採点はしない。
- 自由記述の長文には向かない。長文は flashcard か自己評価に回す。

## cloze

- 文中の重要語を空欄にする。`{{blank:id}}` と `answer.blanks` の ID を一致させる。
- 空欄は1つの Note に詰め込みすぎない。前後の文脈で答えが決まるようにする。

## flashcard

- 用語と説明、公式と意味など、一問一答。
- 自動採点できないため、FSRS は手動評価になる。
- 表面だけで答えが推測できるカードにしない。

## numeric

- 計算、単位換算、有効数字。
- `value` は数値または分数文字列。`unit` を明示する。
- `significantFigures` を要求する場合は問題文にも明記する。
- `acceptedUnits` は正解単位への倍率。単位表と矛盾させない。
- 途中式は `explanation` か Content の math ブロックに書く。

## ordering

- 語順、年代、手順、因果の順序。
- 選択肢2〜12個。`orders` に許容する順序を入れる。
- 初期表示は `initialOrder`。省略時は `options` の順。
- 部分点はない。曖昧な順序になる問題にしない。

## matching

- 用語と説明、元素記号と名称、都道府県と地方。
- 左右2〜12個で同数。全 ID を一意にする。
- `alternatives` に別解の全単射を入れられる。
- 左右に同じ内容を置くと答えが自明になるので避ける。

## hotspot

- 地図、図の中の位置。画像は `assets` の ID を参照。
- 座標は画像左上 (0,0)、右下 (1,1) の正規化座標。
- 図形は `circle` / `rect` / `polygon`。0〜1の範囲、面積0は拒否。
- 小さすぎる領域は Warning。実座標クリックなので旧20×20グリッドを前提にしない。
- 地図の形と正解領域が一致しているか、画像を見て確認する。
- 重なり領域は採点上許容されるが、正解が曖昧になるなら分ける。

## labeling

- 細胞図、回路図、地図の部品にラベルを置く。
- `targets` は正規化座標と `alt`。`labels` は Content。
- 配置先とラベルは1〜50個で同数。`pairs` は全単射。
- 画像内の位置とラベルの意味が一致しているか確認する。

## 使わない形式

- 現在のスキーマにない形式を独自に追加しない。
- 自由記述の意味採点、複合単位、温度オフセットは未対応。代替形式にする。
